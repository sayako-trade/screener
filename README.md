# 5日線-10日線クロス スクリーナー

東証の全銘柄から、5日線と10日線がクロスした当日の銘柄を毎日自動で探して、
結果をWebページに出す。GitHub Actionsで平日17:00に実行。

公開ページ: `https://<ユーザー名>.github.io/<リポジトリ名>/`

---

## 探している条件

### ゴールデンクロス（買い候補）

| # | 条件 |
|---|---|
| 1 | **当日**、5日線が10日線を上に抜けた |
| 2 | 5日線・10日線が**どちらも上向き**（前日比） |
| 3 | 5日線・10日線が20日線より**下**でクロスし、その足が20日線に届いている |
| 4 | その日が**陽線**（終値 > 始値） |

### デッドクロス（売り候補）

| # | 条件 |
|---|---|
| 1 | **当日**、5日線が10日線を下に抜けた |
| 2 | 5日線・10日線が**どちらも下向き**（前日比） |
| 3 | 5日線・10日線が20日線より**上**でクロスし、その足が20日線に届いている |
| 4 | その日が**陰線**（終値 < 始値） |

条件3は2つ見ている。

1. **クロスした地点が20日線のどちら側か。** ゴールデンクロスなら5日線・10日線が
   ともに20日線より下。安値圏からの反転を拾うのが目的なので、20日線の上での
   クロス（上昇局面の継続）は落とす。デッドクロスはその逆。
2. **その足が20日線に届いたか。** ゴールデンクロスなら `高値 >= 20日線`、
   デッドクロスなら `安値 <= 20日線`。ヒゲでかすっているだけでも成立する。
   足全体が20日線の反対側にあって一度も触れていないものだけを落とす。

「惜しかった銘柄」には、1で落ちたものは「20日線より上（下）でクロスした」、
2で落ちたものは「20日線より下（上）に離れている」と表示される。

### 並び順

直近6か月（120営業日）の高値・安値でレンジを作り、終値がその中のどこにいるかを％で出す。
0%が安値、100%が高値。

- ゴールデンクロス → **低いほど上位**（安値圏）
- デッドクロス → **高いほど上位**（高値圏）

★は初期設定で「安値20%以下 / 高値80%以上」。ページ上で変えられる。

### 惜しかった銘柄

条件1（クロス当日）は満たしたが、2〜4のどれかが欠けた銘柄。
満たしていない条件が少ない順、次に売買代金が多い順で最大10件。

## 絞り込み（ページ上で変更可）

| 項目 | 初期値 |
|---|---|
| 株価 | 1,000〜2,000円 |
| 売買代金（20日平均） | 10億円以上 |
| ★のライン | 安値20% / 高値80% |

Pythonは判定だけして、クロスした銘柄を**全部**HTMLに埋め込む。
絞り込みはブラウザ側でやるので、数字を変えると即座に結果が変わる。
設定はブラウザに保存され、次に開いたときも維持される。

売買代金は `終値 × 出来高` の20日平均。出来高（株数）ではなく金額で見ているのは、
単価の安い銘柄が上位を占めてしまうのを避けるため。

## ファイル

```
screener.py                    判定スクリプト本体
template.html                  出力ページのひな形
requirements.txt               必要なライブラリ
.github/workflows/screener.yml 実行スケジュール
data/tickers.json              銘柄一覧のキャッシュ（30日で自動更新）
data/last_date.txt             最後に処理した日付
docs/index.html                出力結果（GitHub Pagesが公開する）
```

## データの出どころ

- 株価: yfinance（Yahoo Finance）。無料、APIキー不要
- 銘柄一覧: JPXの上場銘柄一覧（data_j.xls）。内国株式のみ、ETF・REITは除外

## 実行タイミング

平日 17:00 / 17:30 / 18:00 JST の3回。大引けは15:30なので、
17:00の時点で当日分が揃っていなければ何もせず終わり、30分後にもう一度試す。

- 当日分のデータがまだない → 何もしない（前回の結果がページに残る）
- すでにその日を処理済み → 何もしない
- 祝日 → 当日分のデータが出ないので、自動的に何もしない

Yahooはまとめて叩くとレート制限してくる。取得に失敗したチャンクは
30秒・60秒と待って3回まで粘り、それでも取れなかった銘柄が全体の1割を超えたら
**ページを書き換えずに終了する**（終了コード1）。スカスカの結果で前回の結果を
上書きしてしまうのと、`last_date.txt` に日付を書いて以降のリトライを
潰してしまうのを防ぐため。

## 手元で試す

```bash
pip install -r requirements.txt
python screener.py --force    # 日付チェックを飛ばして強制実行
```

`--force` を付けると、当日分のデータがなくても最新の日足で判定する。
土日や夜中に動作確認したいときに使う。

## セットアップ

1. リポジトリを作る（**public**にする。無料プランではprivateだとGitHub Pagesが使えない）
2. このファイル一式を置く。`screener.yml` は `.github/workflows/` の中へ
3. Settings → Pages → Source を「Deploy from a branch」、ブランチ `main` / フォルダ `/docs`
4. Actions タブ → screener → Run workflow で手動実行して動作確認

手動実行には `force` のチェックボックスがある。土日祝や大引け前は当日分の日足が
まだ無いので、チェックを入れないと何もせずに終わる。動作確認のときは入れる。

## 変えるときのメモ

- 条件そのもの → `screener.py` の `judge()`
- 移動平均の日数 → `judge()` の `ma5` / `ma10` / `ma20`
- レンジの期間 → `RANGE_DAYS`（120営業日 ≒ 6か月）
- 見た目・絞り込みの初期値 → `template.html` の `DEFAULTS`
- TradingViewのリンク先レイアウト → `template.html` の `TV`

ボリンジャーバンドは判定に入れていない。チャートを開いて目視で確認する運用。
